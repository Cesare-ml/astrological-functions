# Sourced house placement matrix — F3 experimental

**Status: IMPLEMENTED_ISOLATED** (not a release and not a real Rust/JPL integration).

`buildSourcedHousePlacementMatrix` presents an explicitly selected **two- or three-system house comparison** in a stable matrix suitable for future VirgoStars Desktop consumers. It composes the existing `compareHousePlacementsWithSourcedPoints` function; no house cusp model, astronomical position, observer geometry, zodiac projection or interpretation is calculated here.

## Dependency chain

- PR #43: generic two-method house placement facts
- PR #48: strict caller-declared source agreement between house sides
- PR #55: strict same-source checks between planetary positions and house sides
- **This slice**: bounded two/three-method comparison matrix, stacked on PR #55
- Existing method producers/consumers are separate: Whole Sign #39, Equal Ascendant #29, Porphyry #40 / adapter #53. The producer branches are **not copied** into this PR.

## API example (synthetic, not scientifically verified)

```js
import {buildSourcedHousePlacementMatrix} from './src/sourced-house-placement-matrix.mjs';

// Both arguments are already-computed, correctly declared {snapshot, source}
// house envelopes; 'positions' is an explicit caller-asserted snapshot.
// All three method outputs and every position must refer to the SAME declared
// UTC instant, zodiac, observer, kernel, engine version, time model,
// correction convention and calculation profile.
const matrix = buildSourcedHousePlacementMatrix({
  birthTimeKnown: true,
  methods: [wholeSign, equalAscendant, porphyry], // explicit display order
  positions: {
    source: wholeSign.source,
    provenanceStatus: 'CALLER_ASSERTED_NOT_INDEPENDENTLY_VERIFIED',
    points: [
      {id:'SUN',longitudeDeg:0},
      {id:'MOON',longitudeDeg:345},
    ],
  },
});
// matrix.methodNames -> ['WHOLE_SIGN','EQUAL_ASCENDANT','PORPHYRY']
// matrix.rows[0].placements -> [
//   {houseSystem:'WHOLE_SIGN',house:2},
//   {houseSystem:'EQUAL_ASCENDANT',house:1},
//   {houseSystem:'PORPHYRY',house:12},
// ]
// matrix.changedPointIds -> ['SUN','MOON'] (for this synthetic example)
```

The `wholeSign`, `equalAscendant`, and `porphyry` bindings above must be produced by validated, explicit consumer adapters; they are not generated by this function.

## Contract and validation

- Require **2 or 3 distinct house methods**, in caller order. Supported method identifiers inherit the currently existing pairwise comparator: `WHOLE_SIGN`, `EQUAL_ASCENDANT`, `PORPHYRY`. `VEHLOW`, legacy `egizia`, Placidus/Koch/Regiomontanus and arbitrary extra methods do not silently map to these.
- No implicit baseline, system order, birth time, point set, timezone, or zodiac. `birthTimeKnown:true` is required; unknown times fail closed. Sparse arrays, duplicated methods, invalid metadata and missing source snapshots fail.
- **Every other method is compared with the first supplied method** by calling `compareHousePlacementsWithSourcedPoints`. It validates every pair's cusp ordering, exact-cusp ownership, UTC, zodiac, observer, engine/kernel/time model, correction convention, calculation profile and point-source equivalence.
- The input `positions.points` uses the existing bounded 0–128 named point list; no extra planet defaults are inferred.
- `rows` are returned in the supplied point order. `placements` in each row follow the `methods` order and are immutable. `changed` is true when at least two systems place a point into different house numbers. `changedPointIds` preserves the point order.
- Nested result arrays, rows, placements and source are frozen; output is JSON serializable.
- Status is always `MATCHING_CALLER_ASSERTED_SOURCES_NOT_INDEPENDENTLY_VERIFIED`. Matching self-reported metadata does **not** establish physical/astronomical accuracy or trusted provenance. The app must verify actual upstream Rust/WASM outputs and proper reference center/correction semantics before relying on this for real natal charts.
- **Same-source topocentric restriction:** this is an opt-in preview for all sources declaring the exact same `TOPOCENTRIC/APPARENT/ECLIPTIC_OF_DATE` context; this is not a universal substitute for mixed geocentric-planet/topocentric-house models. A separately specified model and independent validation are required.
- No Swiss Ephemeris, third-party ephemeris code, secrets, user birth data, rendering, production routes or package export changes.
